# 評価ツール（`python -m makeup_cam.evaluate`）

学習モデルの仕上げが、通話で使える状態かどうかを調べるツールです。動画を実際のパイプラインに通して、ちらつき、崩れ、本人らしさ、遅れを測り、合否を出します。設計の約束ごとは `contract-plan-b.md` の §9 にあります。

**このツールが見ているのは「崩れていないか」です。メイクの見た目の良さは示しません。** 本物のメイクのモデルはまだなく、ここにある閾値はすべて最初の提案です。

## 使い方

```bash
# モデルの評価（.venv-neural。onnxruntime-directml が要ります。合格にはこの全部が必要です）
python -m makeup_cam.evaluate --model フォルダ --measure-fps --soak-minutes 30 --identity-model 顔認識モデル.onnx --identity-licence "ライセンス"

# プリセットだけの評価（.venv でも動きます）
python -m makeup_cam.evaluate --clips "動画*.mp4" --preset natural --out 保存先

# すでに処理した動画を測る（対の参照動画は任意）
python -m makeup_cam.evaluate --clips 入力.mp4 --rendered 出力.mp4 --reference 参照.mp4 --out 保存先
```

| 引数 | 意味 |
|---|---|
| `--model DIR` | `model.onnx` と `model.json` のあるフォルダ。なければ従来のメイクだけを測ります |
| `--clips GLOB`（`--video`） | 動画。既定は `.test-media/testvids/*.flv`。自分で撮った動画も渡せます |
| `--preset NAME` / `--settings FILE` | 設定。既定はモデルの `input_preset`、モデルがなければ natural |
| `--out DIR` | 保存先。崩れの切り抜きには顔が写るので、git の管理下のフォルダは受け付けません |
| `--reference FILE` | 対になる参照動画。`--rendered` があれば比較の基準になり、なければ差の参考値（`paired_abs`）だけに使います |
| `--rendered FILE` | すでに処理した動画を測ります。パイプラインの出力は使いません |
| `--frames-per-clip N` | 1 本あたりのフレーム数の上限 |
| `--strength X` | 測るときの強さ（0〜1）。既定は 1。1 より小さいと判定は「未完了」止まりです |
| `--measure-fps`、`--fps-seconds S`、`--fps-rounds N` | 実際の時間で流して、フレームレートと処理時間を測り、レポートに書きます。仮想カメラは開きません。1 回の長さは既定で 15 秒、モデルありを流す回数は既定で 3 回で、いちばん悪い回の値で判定します。送信の分として毎フレーム 1.5 ms を足します（見積もりです）。モデルなしでも使えます。モデルありでは、従来のメイクにいちばん時間がかかる動画と中くらいの動画で、評価する設定と `natural` の両方を測り、最悪の値で判定します（顔の大きさだけでは決まりません。髪の面積でも変わります）。1 組につき S 秒を 3 回（従来、モデルあり、従来）流すので、既定の 30 秒で最大 6 分かかります |
| `--soak-minutes M` | 実際の時間で M 分流します。30 分未満なら判定は「未完了」止まりです |
| `--no-sway` | 揺らした動画とうなずく動画での確認を省きます |
| `--identity-model PATH`、`--identity-licence TEXT` | 任意の顔認識モデルと、そのライセンス（レポートに書きます） |
| `--deepfake-report FILE` | 自分で動かした検出器の結果。下の「検出器のスコア」を見てください |
| `--no-update-metadata` | `model.json` の `evaluation` を書き換えません |

終了コード: 0 合格、1 不合格、2 未完了、3 評価できなかった。

出力: `evaluation.json`（機械用）、`report_ja.md`（日本語、すべての閾値と崩れの基準つき）、`events/<クリップ>/<種類>_<フレーム番号>.png`（入力、基準、出力、8 倍にした差）。モデルを指定すると、モデルのフォルダの `evaluation.json` と `model.json` の `evaluation` も書き換えます。`evaluation.json` に入るのはクリップ名だけで、パスは入りません。ただしクリップ名はファイル名なので、名前に個人情報を入れないでください。

アプリの設定、プリセット、モデルのファイルは変更しません（`model.json` の `evaluation` だけは例外です）。

## 何と何を比べるか

| モード | 条件 | 基準 |
|---|---|---|
| `classic` | `--model` あり | 同じ実行の、`neural` の直前の従来の出力。同じランドマークとマスクから作るので、「重み 0 の場所はビット単位で同じ」を確かめられます |
| `input` | `--model` なし | 入力の動画 |
| `paired` | `--rendered` と `--reference` | 対の参照動画 |

`input` と `paired` では、メイクそのものが大きな変化なので、ビット単位の確認はしません。いくつかの閾値もゆるくなります。

動きの少ない動画では「メイクが顔に遅れる量」を測れません。そのため、渡された動画のうち最大 8 本は、左右にゆらしたものも測ります（`<クリップ>+sway`）。そのうちの 4 本は、うなずきとお辞儀を足したものも測ります（`<クリップ>+nod`）。どちらも 2D の変形で、本物の頭の動きではありません。

モデルの差分は `input_preset` の出力に足すものとして学習されています。`off` から学習したモデルを `--preset natural` で測ると、メイクが二重にかかった状態を測ることになります。実時間の計測だけは、予算が `natural` を前提にしているので、どのモデルでも `natural` でも測ります。

## 判定

- **不合格**: 測った指標が 1 つでも閾値を外れた。
- **未完了**: 外れた指標はないが、未実施の必須指標がある。測ったフレームが 1000 未満のときも同じです。
- **合格**: すべて測って、すべて閾値の内側。ただし代用品（`stand_in: true`）は、判定がどうであれ `eligible_for_calls: false` です。

顔認識モデルの類似度（`identity_cosine_p01`）は必須指標のままです（契約 §9.3 のとおり）。評価そのものはこのモデルなしで動きますが、その場合の判定は「未完了」止まりで、通話には使えません。検出器のスコアと `paired_abs` は参考情報で、判定には入りません。

崩れの回数（`breaks_per_30min`）は、短い実行では低さを示せません。そのため、次のように扱います。

- 30 分以上の実行: 長時間の実行と品質の確認の両方の崩れを足して、合わせた時間で 30 分あたりに直し、閾値と比べます。長時間の実行では顔の検出点を見ないので、品質の確認で見つかった崩れは長時間の実行が無事でも消えません。
- それより短い実行: 閾値の範囲を超える数が出たら不合格です。そうでなければ未実施で、換算値は参考として表に出ます。

## 崩れの種類

| 種類 | 何を見るか |
|---|---|
| `spike` | 顔に合わせたクロップの中で、一瞬だけ局所的に変わった。モデルありのときは、基準の絵がその場所で同じ瞬間に変わった分の 4 分の 1 を引いてから見ます（まばたきで絵が 26 階調動くときに、差分が 3 階調動くのは崩れではありません）。入力と比べるときは、動き続ける目と口を除きます |
| `off_target` | 描画に使ったランドマークが顔からずれている、または唇の色が唇の外に出ている |
| `landmark_jump` | 描画に使ったランドマーク、または出力から検出したランドマークが飛んだ |
| `teeth_altered` | 口の内側がビット単位で変わった（`classic`）、または口の内側のエッジが変わった |
| `eyes_altered` | 目の開口部について同じ |
| `background_changed` | 変更禁止の領域がビット単位で変わった（`classic`）、または遠い背景が変わった |
| `paint_behind` | メイクが、顔のいた場所に大きく残っている。15 フレームの窓で 3 フレーム以上の遅れです（顔全体で測るものと、モデルありの場合に一部分で測るもの）。小さな遅れは指標の `paint_lag_frames` と `paint_lag_local_frames` が見ます |
| `face_lost` | 基準では顔が見つかるのに、出力では 2 フレーム続けて見つからない |
| `frozen` | 入力は動いているのに、出力が 3 フレーム続けて止まっている |
| `identity_shift` | エッジの構造か検出点が、3 フレーム続けて大きく変わった |
| `result_rejected`、`health_fall`、`worker_restart` | ランタイムの統計から。モデルの結果の破棄、強さの低下、ワーカーの再起動 |

## 本人らしさ

追加の依存なしで、次の 4 つを測ります。

- `landmark_shift_p99`: 出力と基準から別々に検出した点のずれ。
- `identity_geometry_p99`: 同じずれから相似変換を除いたもの。顔の比率の変化を見ます。
- `identity_structure_p01`: 目、鼻、口のまわりのエッジの相関（素顔との比較）。
- `warp_flow_px`（モデルあり）: 基準と出力の間のオプティカルフロー。色を変えるだけなら中身は動かないので、中身が動けば形を変えています。上の 3 つは、検出点が付いてこない形の変化を見逃します（鼻を 30 % 広げても反応しませんでした）。

検出点は別の人の顔を貼っても同じ場所に出ることがあり、形だけでは見分けられない場合があります（下の表の `swap_warped`）。構造の相関はその場合も下がりました。ただし、これらは「本人であること」の証明ではなく、大きく変わったときに気づくための目安です。

### 任意の顔認識モデル

`--identity-model` は、OpenCV の `FaceRecognizerSF` の形式のモデルを読みます。このツールは同梱もダウンロードもしません。ライセンスの確認は使う人の責任で、`--identity-licence` に書いた内容がレポートに残ります。テストはこのモデルを必要としません。

試した結果は、下の「顔認識モデルでの試行」にあります。

## 止まっている破綻

ちらつきや遅れは時間方向の変化を見るので、ずっと同じ場所にある破綻は見えません。そのため、モデルありのときは次も測ります。どれもクリップの中央値で判定します。

- `seam_edge`: 差分の中の鋭いエッジのうち、絵そのものにエッジがない場所のもの。顔を横切る段差や格子が出ます。絵のエッジに沿った変化は、その強さの 6 割まで数えません。
- `side_cast`: 顔の左右で差分の平均がどれだけ違うか。片側だけの色かぶりです。
- `skin_cast`: 肌全体の差分の平均。顔全体の色かぶりです。
- `rim_change`: マスクが確信を持っていない帯（顔の外）の変化。壁、襟、肩に塗っていないかを見ます。ランタイムはマスクが 0.3 未満の場所には描けません（`geometry.MASK_SURE`）。
- `paste_drift_p99`: 貼った差分と顔のずれ（弱めずに貼ったフレーム）。ランタイムの測定値です。

- `frame_locked_ratio`: 顔が動いている間、変化が顔の座標とフレームの座標のどちらで止まっているかの比。1 を超えると、顔よりフレームに付いています。フレームに固定された貼り付きが出ます。モデルの変化は絵に応じて両方で動くので、比だけを見ます。顔が動かない動画では普通のチークと区別できないので、`+sway` と `+nod` でだけ値が出ます。

## 検出器のスコア（任意のフック）

`--deepfake-report` は、**自分で用意して自分で動かした**検出器の結果を読んで、レポートに表示するだけです。

```json
{"output_score": 0.12, "reference_score": 0.10, "detector": "検出器の名前"}
```

- これは利用者が自分で確認するための、品質についての参考情報です。判定には使いません。
- スコアが良くても、何も保証しません。
- このツールは加工を隠すためのものではありません。
- このツールは検出器を同梱せず、ダウンロードせず、呼び出しません。検出器を相手に学習することも、検出を避ける機能もありません。

契約 §9.2 の暫定値から変えたのは次の 4 つです。測定から分かった理由を挙げます。

- `flicker_ratio`（1.10、1.25 → 1.08、1.15）: もとの値では 2 階調のノイズをかなり見逃しました。
- `mouth_band_edge_corr`（0.98 → 0.90）: 少し肌をなめらかにするだけのモデルの代用でも 0.923 まで下がります。歯そのものは `mouth_inner_edge_corr` と `mouth_interior_max` が見ています。
- `landmark_shift_p99`（0.015 → 0.06）: ほぼ同じ 2 枚の画像でも、検出モデル自身が 0.045 までずれます。3 フレームの中央値を取ってからの値です。
- `deepfake_margin`（0.05 → 閾値なし）: 判定に入れると、検出器を通すことが合否の条件になります。ここでは参考表示だけにしました。

## 検証

**条件**: CREMA-D の女性 11 人の 44 本（3218 フレーム、107 秒）。960×720 に拡大して 1280×720 に余白をつけています。実際のパイプラインとモデル（`natural`、`polished`、`strong`）を CPU で動かし、`python -m makeup_cam.evaluate_validate` で集計しました。**本物のメイクのモデルでの結果ではありません。** 「モデル役」は、契約の貼り付け式で作った、学習を含まない 2 種類の代用です（固定の色合い `tint`、少しぼかす `smooth`。後者は 1 フレーム前のクロップから作ります）。

`input/` は入力との比較（出力は従来のプリセット）、`classic/` は従来の出力との比較（出力はモデル役）です。`pan` は同じ動画に左右のゆれを足したものです。

強さの段階を変えた実行は 11 本だけです（各行の「本」の数）。

閾値はこの 44 本から選んだので、下の数字はその同じ素材での値です。素材に合わせすぎていないかは、後で述べる半分ずつの確認で調べました。

ゆらした実行（`pan` と `pan_classic`）は最終のコードで測り直しました。それ以外は、同じ測定コードで測ったフレームごとの値を、最終の閾値で数え直したものです。

## 分かっていないこと

- 完全な評価の中で測ると、従来のメイクそのものが 1.4〜2 ms 遅く出ます（1073 で中央値 31.4〜32.0 ms、単独で 30.0 ms）。品質の確認 16 本のあとでは再現せず、`gc.freeze` でも変わらなかったので、原因は分かっていません。モデルありも同じ条件で測るので差は比べられますが、余裕の少ないクリップでは不合格に傾きます。
- 実時間の値は仮想カメラの実際の費用を含みません。毎フレーム 1.5 ms は見積もりです。

- 本物のメイクのモデルでの値。閾値はモデルができたら見直します。
- 横を向いた顔、手が顔にかかる場面、本物のお辞儀（ここにあるのは 2D の変形です）、暗い部屋。CREMA-D はほぼ正面の短い動画です。
- 通話アプリと同時に動かしたときの実時間の値。他の処理のない状態での実時間の値（ここにある数字はすべて、別の処理が動いている状態のものです）。
- 実時間と長時間まで含めて、実際のワーカーで「合格」が出ること。合格への経路は偽のモデルでしか試せていません。
- 長時間の実行は、同じ素材を繰り返すだけなので、素材の多様さは増えません。ランタイムの安定性を見るものです。
- 口の遅れは、検出したランドマークから推定した目安です。実際の音声との同期は測っていません。
- 別の人の顔を見分ける力は、ここで作った簡単な貼り付けに対してのものです。
